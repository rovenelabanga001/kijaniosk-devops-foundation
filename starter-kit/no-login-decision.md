I chose /usr/sbin/nologin over /bin/false because nologin provides a clearer and more explicit denial of interactive access. When a user attempts to log in, nologin displays a message indicating that the account is not available for login, whereas /bin/false silently terminates the session. This makes nologin more suitable for service accounts, as it improves clarity for administrators while still preventing shell access. Both achieve the same security goal, but nologin is more informative and intentional.
